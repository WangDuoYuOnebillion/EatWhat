# 小付，今天吃什么？

> 知道家里有什么,但不知道能做什么 —— 这个应用就解决这一件事。

勾选家里现有的食材,它给出**现在就能做的菜**,附完整做法、每步耗时、热量营养和缺料提示。

---

## 怎么用

**双击 `index.html`** 就行。不用装任何东西,不用联网。

- 手机上(推荐):**部署成一个网址**,微信里点开就能用、能存数据、能加到主屏 —— 步骤见 [DEPLOY.md](DEPLOY.md)。直接发 `index.html` 文件在 iPhone 上基本走不通(微信不预览 `.html`)
- 手机上(临时):把 `index.html` 传到手机,用浏览器打开
- 换设备:复制这一个文件过去即可;数据可在「我的 → 导出数据」搬迁

> 加到主屏后是那只**棕色小碗图标**(`apple-touch-icon.png`),不是网页缩略图 —— 前提是按 [DEPLOY.md](DEPLOY.md) 把图标和 `index.html` 放在同一目录。

**这是一个手机应用。** 电脑上打开也能用,但界面会收成一条居中的手机宽度 —— 因为真实场景都在手机上:站在冰箱前勾食材、在超市里看购物清单、在灶台边看步骤。

数据全部存在浏览器本地(localStorage),不上传任何服务器。如果所在环境禁用了本地存储(比如 Safari 无痕模式),应用照常能用,但会在页面顶部明确提示"刷新后会丢数据"。

## 五个页面

| 页面 | 干什么 |
|---|---|
| 🧺 **选食材** | 分类网格一键勾选。调味料默认算你都有,不用勾。支持按别名搜索(输"番茄"能搜到西红柿) |
| 🍽️ **今天吃** | 三档结果:**现在就能做** / **差一两样** / **凑一凑也行**。可按热量、时长、蛋白质排序。「摆一摆」随机出菜,「配一桌」一荤一素一汤,「一周菜单」7 天不重复 |
| 🧊 **我的厨房** | 长期记录家里有什么。录入只问一句"还能放几天",六个按钮点一下就完事。快坏了的会主动提醒,并在推荐里优先给能消耗它的菜 |
| 🛒 **买菜清单** | 几道菜缺的料自动合并去重(同食材同单位累加),按分类分组,可打勾、可一键复制成文本 |
| ⚙️ **我的** | 份数、营养目标(均衡/减脂/增肌/控糖)、忌口、素食/清真、辣度上限、厨具、调味基础包、收藏、历史、数据导入导出 |

点开任意一道菜可进入**做菜模式**:全屏、单步聚焦、大字号、带计时器、屏幕不休眠。走完最后一步自动记入历史,之后一周内不会再重复推荐它。

## 里面有什么

- **153 道菜**,中式家常为主:炒菜 52 / 炖焖 22 / 汤羹 19 / 凉菜 19 / 蒸菜 10 / 主食 17 / 早餐 9 / 烤箱空气炸锅 5
- **848 个操作步骤**,平均 5.5 步一道,每步带预计耗时;每道菜配 1 条关键经验
- **122 项食材**,含别名、默认保质天数、荤素标记;其中 32 项高频食材置顶
- 份数可切 1 / 2 / 3 / 4 / 6 人,用量和合计热量实时联动

**关于热量:** 营养数据是按配方用量和常用食材成分表推算的**估算值,误差约 ±15%**,应用里也这么标注。同一道红烧肉肥瘦比例不同热量能差三成,所以拿它当趋势参考,别当计数依据。

## 改完数据一定要自检

菜谱和食材是纯手写的数据,退化是静默的 —— 改错一个 id、删掉一个食材,页面照样打开,只是某些食材永远搜不到菜。所以有一个校验脚本守着:

```bash
node check.js
```

**零 error 才算通过**(退出码 0);有 error 会列出来并返回退出码 1,方便挂到提交钩子上。

它检查 7 类问题:

| 类别 | 查什么 |
|---|---|
| 引用完整性 | 菜谱引用的食材 id、厨具 id 是否都存在 |
| id 唯一性 | 菜谱 id、食材 id 有没有重复 |
| 用量与单位 | 每项主料辅料都有正的用量,单位在白名单内(g / ml / 个 / 根 / 片 / 瓣 / 颗 / 勺 / 把 / 适量) |
| 营养自洽 | 标称热量与「蛋白×4 + 脂肪×9 + 碳水×4」的偏差 ≤20%,防止数据自相矛盾 |
| 步骤完整 | 每道菜 ≥3 步、每步有耗时、每道菜有 1 条关键经验 |
| **覆盖度** | **每个「常用」食材至少是 4 道菜的主料**(PRD §10 硬约束) |
| **零孤儿** | **每个食材至少被 1 道菜用到** —— 否则用户勾了它却出不来菜(PRD §10 硬约束) |

最后两条是这个脚本存在的主要理由:它们决定了产品的核心承诺(勾任何常见食材都能得到有意义的结果),而肉眼守不住。

**想确认脚本本身没坏:**

```bash
node check.js --selftest
```

它会往数据里故意注入 8 类错误各一个,验证每一类都能被准确报出。

也可以校验别的文件:`node check.js path/to/index.html`

### 让它自动跑(提交前拦截)

仓库里带了一个 pre-commit 钩子。**clone 下来之后跑一次这句**,之后每次 `git commit` 就会自动校验:

```bash
git config core.hooksPath .githooks
```

> 这一句不能省 —— `core.hooksPath` 是本地配置,不随仓库一起 clone。

钩子只在 `index.html` 进入本次提交时才跑,而且校验的是**暂存区里那一份**,不是工作区那一份。所以"工作区已经改好、暂存的还是坏的"这种情况也会被拦住。

校验不过就中止提交并列出 error。确有理由跳过:`git commit --no-verify`。

### 浏览器里的轻量自检

打开控制台,应用启动时也会输出一次简版自检(食材/厨具 id 引用、菜谱 id 重复)。这是运行时兜底,覆盖面比 `check.js` 小。

`window.EW` 暴露了 `S`(状态)、`RECIPES`、`ING`、`match()`、`render()`,方便在控制台调试。
